# West Peek OS — provider & credential readiness audit

P26 phase 2. Generated by inspecting the installed central Repo Operator credential vault, the West
Peek local vault, the worker source, `wrangler.toml`, and the live production Worker secret list.

**No credential value appears in this document.** Only names, providers, character counts and
readiness metadata — the same discipline the vault itself enforces.

---

> **RESOLVED 2026-08-17.** At audit time the production Worker secret list was empty (`[]`) and no
> AI path could work. The Managing Partner then decided that all AI work flows through OpenRouter
> and authorised West Peek to share the Repo Operator OpenRouter credential. `OPENROUTER_API_KEY`

> It is **configured, not yet externally verified** — no model call has been made.

## 5 · What this audit does **not** claim

- That any AI provider works. None is configured in production; none was called.
- That any candidate key is valid. Every relevant credential is `UNVERIFIED` in the vault — stored
  and present, never probed.
- That the six Cloudflare tokens differ in scope. Their lengths differ (53/53/53/41/32/53), which
  means they are not all the same kind of token, but scope was not inspected.

## 6 · What the audit itself changed — nothing

The audit pass (§§1–5) was **read-only**: no credential rotated, disabled, replaced, deleted or
written, no secret bound, no conflicting credential silently chosen.

The changes recorded in §7 came afterwards, from an explicit Managing Partner decision, and are
listed there rather than folded back into the audit above. Sections 1–5 describe the state as
found; §7 describes what was then done about it.

## 7 · Change log

**2026-08-17 — OpenRouter enabled as the single AI lane.**

Managing Partner decision: all AI work flows through OpenRouter, and West Peek may share Repo
Operator credentials.

- `migrations/0024_enable_openrouter.sql` — sets `enabled = 1` for `openrouter` and nothing else.
- `OPENROUTER_API_KEY` bound as a production Worker secret. Value moved Keychain → pipe →
  `wrangler` stdin: never echoed, never written to disk, never present in argv.
- **Egress was not widened.** The data-class policy seeded at `0004` is untouched, so `CONFIDENTIAL`,
  `RESTRICTED`, `LP_PRIVATE`, `MNPI_SENSITIVE` and `BANKING_RESTRICTED` still cannot reach
  OpenRouter. Only `PUBLIC` and `INTERNAL` may.
- Nothing was rotated, replaced or deleted; the Repo Operator key still serves Repo Operator.
- The West Peek local vault does **not** hold this key — its `vault set` is TTY-only. The name was
  added to `scripts/vault/cloudflare-mapping.json`, so once set interactively,
  `vault:sync:cloudflare` will manage it through West Peek's own path.

Remaining genuine gaps: Fireworks (no key exists in any vault) and Harvey / Norm (no vendor account
exists). Neither blocks operation now that all AI routes through OpenRouter.
